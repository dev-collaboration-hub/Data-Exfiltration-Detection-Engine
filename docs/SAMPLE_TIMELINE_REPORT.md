# Sample Timeline Report

## Purpose

Show an easy-to-read sample Process Behavior Timeline report built from fake process and network events (Milestone M5).

This report is generated by the same path used in production analysis:

```text
Fake process / network observations
        │
        ▼
TimelineEventCollector
        │
        ▼
ProcessTimelineBuilder   → chronological timeline lines
        │
        ▼
TimelineSummaryBuilder   → readable activity summary + soft hints
```

## Scenario

Two processes are observed on an endpoint:

| PID | Process | Behavior |
|-----|---------|----------|
| 4120 | `python.exe` | Starts, opens one remote HTTPS connection, uploads 12.5 MB, downloads 3.2 MB, then disconnects |
| 2204 | `chrome.exe` | Starts shortly after and opens a separate browsing connection |

Input events are deliberately shuffled so the timeline builder must sort them before reporting.

## Global Timeline

```text
10:01:02 | python.exe | Process Seen
10:01:05 | chrome.exe | Process Seen
10:01:10 | python.exe | Connected to 104.18.32.45:443
10:01:12 | chrome.exe | Connected to 142.250.190.78:443
10:01:15 | python.exe | Upload Activity: 12.5 MB
10:01:20 | python.exe | Download Activity: 3.2 MB
10:01:30 | python.exe | Disconnected from 104.18.32.45:443
```

Events appear in chronological order across all processes.

## Activity Summary: python.exe

```text
python.exe was active for 28 seconds.
It connected to 1 remote endpoint.
Total upload: 12.5 MB.
Total download: 3.2 MB.
Most active destination: 104.18.32.45:443.
Hint: Elevated outbound transfer volume observed.
```

Notes:

- Soft hints provide context for later M6 detection work.
- M5 does **not** emit final security alerts.

## How To Reproduce

```bash
c++ -std=c++17 -o timeline_system_tests tests/process/TimelineSystemTests.cpp
./timeline_system_tests
```

The system tests build this exact fake incident and verify:

- Fake process events become `process_seen` timeline entries
- Fake network / transfer events become connection and upload/download entries
- Events are sorted into the correct chronological order
- Per-process timelines stay isolated by PID
- Sample report strings match the readable output above
